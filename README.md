# VR Safety Trainer

Учебный проект Фадеева Михаила. Аналитический этап, 3 ноября 2026 года.

## Проверка работающих компонентов

Требуется Python 3.10 или новее. Сторонних библиотек нет. Выполнить из этой папки:

```console
python -m unittest discover -s analytics -v
python analytics/assess.py --scenario data/scenario.json --session data/session_good.json --out results/good.json
python analytics/assess.py --scenario data/scenario.json --session data/session_late.json --out results/late.json
```

Ожидается: 14 успешных тестов; первая попытка — 100 баллов, passed=true; вторая — 60 баллов, passed=false, критический шаг leave_zone выполнен поздно.

Критерии и события синтетические. Это проверка алгоритма, а не инструкция по действиям при реальной аварии. Порог, веса и сроки задаёт учебный сценарий. Они не являются нормативными значениями.

`validate_session` проверяет журнал. `evaluate_session` оценивает последовательность и сроки относительно старта попытки. Раннее действие не продвигает указатель; его нужно выполнить снова в правильном порядке. Нарушение порядка критического шага сохраняется как критическая ошибка даже после исправления. Повтор принятого действия и неизвестное действие не дают баллов. `summarize_reports` вычисляет сводку. Passed — учебный результат и рекомендация для инструктора, не юридический допуск.

## Unity

Откройте `UnityClient` через Unity Hub в Unity 6000.3.7f1. После активации лицензии выберите `Training → Create demo scene`, затем Play. Кнопки записывают события; Export сохраняет JSON в `Application.persistentDataPath` (путь выводится на экране и в Console). Передайте файл в Python-компонент через `--session`.

Это заготовка клиента с настольной проверкой событий. OpenXR, взаимодействие контроллеров, веб-панель и интеграция СДО ещё не реализованы. C# скомпилирован в Unity 6000.3.7f1, сцена создана и запущена в Play, проверены три действия и экспорт JSON. Журнал `data/session_unity.json` передан в Python; результат находится в `results/unity-session.json`. В этой ручной проверке действия выполнялись после предельных сроков: получены 0 баллов и рекомендация повторить обучение. Журнал успешной сборки: `results/unity-verify.log`.

## Модели и доказательства

- `models/training-process.rsf` — редактируемая модель IDEF0 для Ramus.
- `models/logical-model.html`, `.svg`, `.json` — логическая ER-модель, открывается локально в браузере; физическая БД не требуется.
- `models/algorithm-*.png` — блок-схемы процедур.
- `results/*.json`, `tests.txt`, `verification.html` — фактический вывод запуска.
- `screenshots/` — снимки приложений, включённые в отчёт.

Репозиторий локальный. Удалённый GitHub-репозиторий и публикация не создавались. История доступна командой `git log --oneline`.
